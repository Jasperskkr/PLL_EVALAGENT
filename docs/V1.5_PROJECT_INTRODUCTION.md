# PLL_EVALAGENT V1.5 Project Introduction

> 新会话交接文档：V1.5 多参数行为级规格分配

## 1. 新会话首先要知道的结论

本项目已经完成 V1.0 的确定性一维规格分配闭环，以及 Phase 1 的 Block
语义和 Typed Graph 冻结。下一阶段正式命名为：

```text
V1.5：多参数行为级规格分配
```

### 2026-09-22 implementation update

Canonical `PN anchor × k1` 已完成 234 点确定性评测。18 个 k1 slice 中，9 个已完成：

```text
System boundary
→ frozen-context boundary BlockTB contract
→ fixed 1.5 dB engineering margin
→ discrete PN_BlockSpec(k1)
→ one candidate BlockTB + independent SystemTB replay per mapped slice
```

另外 9 个 slice 因当前搜索范围内无 System-feasible point 而保持未分配。当前结果只对
列出的离散 k1 值有效，不声明连续插值、Pareto、全局 k1 requirement 或 transistor-level
signoff。多维 evaluator 接入通用 `AllocationModule` 仍待完成。

### 2026-09-23 formal 2-D BlockSpec update

在上述离散 allocation 之后，已完成 8 个 off-grid k1 中点的边界 holdout、measured
`kvco_max` 轴资格审查，以及 16 个边界邻近候选的联合 contract 验证。当前正式行为级
二维规则为：

```text
1.54 <= measured kvco_max <= 1.84 GHz/V
measured worst PN <= PN_spec(measured kvco_max)
```

其中 `PN_spec` 在 1.54、1.59、1.64、1.69、1.74、1.79、1.84 GHz/V 处有 7 个
canonical 节点，节点间使用分段线性关系；PN margin 为 1.5 dB。Kvco 每端 50 MHz/V
是显式选择的网格步长 guard band，不是由仿真推导出的物理不确定性。8 个规格内候选
全部通过 BlockTB/SystemTB，内部 false positive 为 0，独立 replay 一致。

该结果已经写入 `formal_2d_blockspec.json` 生成器和报告，完整输入、输出、复现顺序和
claim boundary 见 [`docs/V1.5_CURRENT_INPUT_OUTPUT.md`](V1.5_CURRENT_INPUT_OUTPUT.md)。
正式结果仍限定于冻结 synthetic 行为模型和单一 context，不宣称必要条件、PVT 鲁棒性或
transistor-level signoff；最终联合规格接入通用 `AllocationModule` 和独立 Graph audit
仍是后续工程化工作。

V1.5 不重写 V1.0，也不改变已经验证过的数值基线。它要在同一个 VCO
行为模型、SystemTB、BlockTB 和 Typed Graph 上，把：

```text
一个 System 指标 ↔ 一个 VCO 变量的局部标量映射
```

扩展为：

```text
多个不可修改的 SystemSpec constraints
        ↓
多个 VCO internal design knobs 组成的 DesignVector
        ↓
context-aware VCO Behavior vector / Capability Region
        ↓
BlockTB feasible ∩ SystemTB feasible
        ↓
带残差、validity、选择规则和完整证据的候选集合
```

对当前 Graph 的准确判断是：

> **现有 Graph 的核心语义和类型系统可以支撑 V1.5，不需要再发明一套图；但当前 Graph compiler、audit 和 allocation runner 主要编译 V1.0 标量结果，V1.5 的多维搜索、区域 artifact、通用约束检查和 Pareto 选择尚未实现。**

因此，新会话应把 Graph 当作 V1.5 的可追溯数据骨架和治理边界，而不是把它误认为已经实现的多维优化器。

## 2. 项目要解决什么问题

项目的长期主线是：

```text
PLL SystemSpec
→ Behavioral Design Space
→ BlockSpec Allocation
→ Candidate / Realized Instance
→ context-aware BlockTB
→ SystemTB re-validation
→ traceable Evidence
```

其中：

- Problem 1：建立最小但足够的 Block behavioral abstraction，明确 architecture、Behavior、context、influence、measurement 和 validity；
- Problem 2：在这个可信的 behavioral design space 中分配 Block Requirement、搜索 Candidate，并用 BlockTB 和 SystemTB 双重验证。

V1.0 使用人工定义的固定 VCO Block 完成了 Problem 1 pilot，并完成 Problem 2
的一维确定性证明。V1.5 的任务是推进 Problem 2 的多参数版本，同时用新结果反向检查
Problem 1 的 abstraction 是否缺少变量、耦合或有效域。

## 3. 当前已经证明的 V1.0 基线

当前 canonical chain 是：

```text
SystemSpec
→ deterministic SystemTB
→ residual
→ characterization / finite-difference sensitivity
→ PN internal-anchor boundary search
→ frozen-context VCO measurement
→ measured VCO requirement
→ candidate search
→ realized VCO instance
→ context-aware BlockTB
→ independent SystemTB replay
```

固定 case：`v1/cases/vco_mapping_01.json`。

| 项目 | 已验证结果 |
|---|---:|
| PLL jitter limit | 80 fs |
| Initial jitter | 83.367 fs，FAIL |
| PN internal-anchor boundary | -116.358121 dBc/Hz |
| Worst measured PN at boundary | -113.511151 dBc/Hz |
| Required measured VCO PN | -113.511151 dBc/Hz |
| Recommended VCO PN（1.5 dB margin） | -115.011151 dBc/Hz |
| Selected synthetic candidate | `candidate_low_noise` |
| Final jitter | 41.783 fs |
| Final lock time | 36.520 us |
| Final frequency | 5 GHz |
| Final SystemTB | PASS |

这里必须保持以下语义链，不能把四个量混为一个量：

```text
pn_anchor_1mhz_dbc_hz
    internal model / candidate knob
        ↓ Block model under context
phase_noise_1mhz_dbc_hz
    point Behavior metric
        ↓ BlockTB aggregation
worst_phase_noise_1mhz_dbc_hz
    measured Behavior aggregate
        ↓ allocation + margin
phase_noise_1mhz_max_dbc_hz
    VCO Block Requirement
```

附加的 deterministic scalar mapping suite 还执行了：

```text
jitter      → PN
lock time   → k1 / Kvco
power       → nominal power
frequency   → f0 / tuning coverage
```

它们证明同一个 workflow 可以处理多种局部一维映射，但不是“多个变量同时分配”。
其中 lock-time/Kvco 和 frequency/f0 在宽扫描范围内存在可行窗口或非单调性，
只能在记录的 local validity bracket 内使用，不能宣称全局唯一边界。

## 4. 当前 Graph 到底是什么结构

### 4.1 对外的 Block Graph 语义只有四种角色

```text
architecture
    Block、真实功能/物理端口、信号连接和 context input

behavior
    在指定 context 下可测量/可计算的 Block 输出
    例如 frequency、phase noise、Kvco、power

influence
    Behavior 如何通过明确机制影响 System metric
    例如 PN → noise transfer/integration → jitter

evidence
    characterization、sensitivity、boundary、BlockTB、SystemTB、audit、provenance
```

这是 `semantic_role` 的公开含义。不要重新引入
`interface/behavior/allocation/verification`，也不要把 workflow object 当作第五层。

### 4.2 Workflow objects 是图中的对象，不是 Block Graph layer

```text
SystemSpec
BlockRequirement
DesignSpace
Candidate
RealizedInstance
CapabilityRegion
MeasurementContract
ValidityDomain
Evaluation / Evidence
```

这些对象把一次 allocation run 串起来。例如：

```text
SystemSpec
  allocates → BlockRequirement
  constrains → System metric

Candidate
  candidate_of → DesignSpace
  realizes → RealizedInstance

RealizedInstance
  evaluates → BlockTB
  evaluates → SystemTB

BlockTB PASS candidate
  candidate_of → CapabilityRegion

SystemTB
  verifies_requirement → SystemSpec
```

### 4.3 `plane` 是内部权限/来源分组，不是公开语义层

Graph JSON 还保存：

```text
plane = schema / contract / realization / evidence
authority / scope / mutability / provenance
```

它们用于限制 Agent 权限和区分“假设、实例、事实”：Agent 以后可以提出 Contract
或 Candidate，但不能把 proposal 直接改成 Realized Result，也不能伪造 Evidence。
`plane` 与四个 `semantic_role` 正交，不能混为一套分层。

## 5. 为什么现有 Graph 可以支撑 V1.5

| V1.5 所需能力 | 当前支撑 | 代码/结构证据 | 仍需补齐 |
|---|---|---|---|
| 一个 Candidate 带多个内部变量 | 基本具备 | `DesignVector.values` 是字典，compiler 可一次编译多个合法 `VCOParams` 字段 | 正式的多维 search-space schema、bounds 和采样策略 |
| 区分 knob 与 Behavior | 已具备 | `candidate_knob` 与 `behavioral_output` 分开，validator 禁止 knob-as-behavior | V1.5 artifact 中持续执行该规则 |
| 记录多个 sampled candidates | 已具备 | `design_space`、`candidate`、`candidate_of` | 当前 runner 还没有二维/多维采样循环 |
| Candidate → RealizedInstance | 已具备 | `realizes` edge 和 realization compiler authority | 批量 point 的稳定 ID/hash 和去重规则 |
| BlockTB 输出多项 Behavior | 基本具备 | VCO measurement 已输出 PN、Kvco、frequency、power 的 worst/min/max | 通用 Behavior constraint vector，不应只调用 PN requirement 类型 |
| 表示 Capability Region | 基本具备 | `capability_region` node；只有 BlockTB PASS 的 candidate 才能加入 | 当前状态明确是 `sampled_partial_one_dimensional`，需生成真正的多维 sampled region |
| 同时检查多个 SystemSpec | 已具备 | SystemTB 已返回 jitter、lock time、frequency、power 的 checks/residuals | allocator 要把 residual vector 当成联合约束，而不是只选择一个 target check |
| 完整 BlockTB/SystemTB 证据链 | 已具备 | evaluation、context coverage、verifies/validated edges、provenance | Graph compiler/audit 中仍有 PN/jitter 专用节点和硬编码检查，需要增量泛化 |
| 多维 sensitivity / interaction | 未完成 | 现在只有单参数 sweep 和局部 derivative | Jacobian、二维 slice、cross-term/interaction test |
| 多维 boundary / feasible-region search | 未完成 | 只有 scalar bracket/bisection 和一维 candidate grid | deterministic grid/adaptive refinement/region classifier |
| Pareto selection | 未完成 | Graph 能保存候选和属性 | 需先定义显式 objective/cost，再实现 non-dominated sorting 和选择规则 |

因此答案不是“Graph 已经完成多维分配”，而是：

```text
Graph data model / governance seam：可复用
V1.5 deterministic execution engine：待实现
V1.5 graph compiler / audit generalization：待实现
```

建议保留 `graph_version = 2.0` 和现有 semantic roles。只要没有改变公开图语义，
V1.5 不应仅因为多了二维数据就升级或重命名 Graph 版本。

## 6. V1.5 中必须分清的三个空间

这是多维开发最容易出错的地方：

```text
1. Design Space（输入/搜索空间）
   x = [pn_anchor_1mhz_dbc_hz, k1_hz_per_v, ...]
   坐标是 internal candidate knobs

2. Block Capability Region（Block 能力空间）
   b = [worst_phase_noise, kvco_min/max, frequency_min/max, worst_power, ...]
   坐标是在 frozen context 下由 BlockTB 测得的 Behavior aggregates

3. System-feasible Region（系统可行集合）
   F = {x | BlockTB(x, context) PASS 且 SystemTB(x) 的全部 residual ≤ 0}
```

Capability Region 不能直接用 internal knobs 冒充；System-feasible 也不能只凭
SystemTB PASS 而绕过 BlockTB。Block Requirement 是对 measured Behavior 的约束，
不是把搜索参数换一个名字后直接写成 requirement。

## 7. V1.5 推荐的最小实验

第一组正式联合实验建议使用：

```text
DesignVector axes:
  pn_anchor_1mhz_dbc_hz
  k1_hz_per_v

Active System constraints:
  integrated_jitter_s ≤ limit
  lock_time_s ≤ limit

Always checked:
  output frequency tolerance
  power limit
  lock status

Measured VCO Behavior:
  worst_phase_noise_1mhz_dbc_hz
  kvco_min_hz_per_v / kvco_max_hz_per_v
  frequency_min_hz / frequency_max_hz
  worst_power_w
```

这个实验能验证多维 constraint handling、可行域和候选回代，但要保持诚实：当前
synthetic VCO 中 `pn_anchor` 与 `k1` 是可独立设定的模型参数，它们不等于真实晶体管
设计中天然耦合的 PN–Kvco trade-off。因此：

- V1.5-A 可以先证明“多维分配引擎和证据闭环成立”；
- 若要宣称真实 Pareto/trade-off，V1.5-B 必须增加显式耦合的 candidate family、代理模型，或导入真实电路/工程数据；
- 没有显式 objective/cost 时，只能输出 feasible set 和 margin，不应滥用“Pareto”。

## 8. 推荐实现顺序

### Step 0：冻结回归

- 保持 `run_v1_prove.py`、V1 benchmark 数值和现有 23 个测试不变；
- 将 V1.0 标量路径作为 V1.5 的 regression control；
- 不修改 immutable SystemSpec，不让搜索器通过放宽指标制造 PASS。

### Step 1：定义 V1.5 的机器可读 artifact

至少需要：

```text
DesignSpaceDefinition
SampledDesignPoint
BehaviorVector
SystemMetricVector
ConstraintResidualVector
CapabilityRegion
SystemFeasibleRegion
SelectionDecision
```

每个 sampled point 必须带：DesignVector、realized instance、context、BlockTB、
SystemTB、所有 residual、status、model/version 和 provenance。

### Step 2：实现通用联合 evaluator

输入一个完整 `DesignVector`，一次编译为一个 `RealizedInstance`，然后：

```text
BlockTB(realized instance, frozen context)
SystemTB(the same realized instance)
independent constraint evaluator
```

输出完整向量，不只返回一个 target metric。BlockTB 和 SystemTB 必须使用同一
realized instance，最终 selected point 再独立 replay 一次。

### Step 3：先实现确定性二维 grid

第一版优先选择容易审计的 Cartesian grid，不急于上复杂 optimizer：

```text
PN × k1 grid
→ evaluate every point
→ classify Block feasible / System feasible / jointly feasible
→ find local boundary cells
→ optional deterministic refinement
```

所有 axis、步长、bounds、遍历顺序和 tie-break rule 必须写入 artifact，确保可复现。

### Step 4：生成 Capability Region 和 System-feasible Region

- Design Space 保存全部尝试点，包括失败点；
- Capability Region 只收录 BlockTB PASS 的点，并使用 measured Behavior 表示；
- System-feasible Region 只收录 BlockTB、context coverage、SystemTB 全部通过的点；
- 对非单调或多窗口区域直接保留真实拓扑，不强行压缩成一个上下界。

### Step 5：加入显式 selection / Pareto 规则

若只需要一个推荐候选，至少定义：

```text
hard constraints
margin normalization
engineering cost
tie-break order
```

只有在存在两个或更多明确冲突的 objective 时才输出 Pareto front。选中的 candidate
必须能从 objective values 和固定 tie-break rule 唯一复现。

### Step 6：增量扩展 Graph compiler 和 audit

建议新增 V1.5 compiler/adapter，而不是破坏 V1 compiler：

- 每个 sampled point 编译 `Candidate → RealizedInstance → BlockTB/SystemTB`；
- 把 BehaviorVector、residual vector、region membership 和 selection evidence 写入 Graph；
- 把当前 audit 中 PN/jitter 专用的 closure checks 泛化为按 requirement 列表检查；
- 保留 semantic-role、plane、authority、mutability 和 provenance 规则；
- Agent proposal 仍不能直接成为 canonical edge 或 Evidence。

### Step 7：报告与验证

建议输出：

```text
运行时输出目录（默认被 Git 忽略）/
  design_space.json
  sampled_points.csv
  sampled_points.jsonl
  capability_region.json
  system_feasible_region.json
  selection_decision.json
  selected_candidate_replay.json
  vco_pll_graph_v2.json
  graph_audit.json
  summary.md
```

二维可视化可以作为报告，但 JSON/CSV 和 deterministic evaluator 才是正式证据。

## 10. V1.5 完成标准

V1.5 只有同时满足下面条件才能宣布完成：

1. 至少两个 active design axes 被联合采样或搜索，而不是分别做两次一维 sweep；
2. 至少两个 System constraints 对可行域有实际约束作用；
3. sampled set 同时包含 feasible 和 infeasible points，且边界可由相邻点或 refinement 复核；
4. 每个点都有 frozen context 下的 measured Behavior 和 BlockTB 结果；
5. 每个点都有 SystemTB metrics、checks 和 residual vector；
6. Capability Region 与 System-feasible Region 被明确区分；
7. selected candidate 使用同一个 RealizedInstance 完成 BlockTB、SystemTB 和 independent replay；
8. Graph 可以追溯 `SystemSpec → constraints/requirements → point → instance → TB → verdict/evidence`；
9. Graph audit 对所有 sampled/selected points 通过，失败点不会被写入 Capability Region；
10. V1.0 和 V1.5 主 runner 可重复执行，V1 benchmark 数值不漂移；
11. 报告明确区分 synthetic behavioral proof 与 transistor-level signoff；
12. 若输出 Pareto，objectives、normalization、dominance 和 tie-break 全部显式且可复现。

## 14. 本阶段的 claim boundary

V1.5 要证明的是：

> 在固定 PLL architecture、行为模型、context 和 measurement contract 下，可以从不可修改的多项 SystemSpec 出发，对多个 VCO 行为设计变量进行确定性联合搜索，得到经过 BlockTB 与 SystemTB 双重验证、带有效域和证据链的行为级可行集合与推荐候选。

V1.5 不证明：

- synthetic VCO candidate 已经能由晶体管电路实现；
- 当前 PN–Kvco–power 关系等同于真实工艺下的 trade-off；
- Graph 自己完成了数值优化；
- Agent 已经自动构建 Block 或自动完成 allocation；
- 行为级 PASS 等价于 SpectreRF/PSS/PNOISE 或 silicon signoff。
