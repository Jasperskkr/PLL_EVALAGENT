# 三个核心问题：现状、缺口与下一轮验收

日期：2026-11-04。依据：用户本轮提出的完整 SystemSpec、模块变量范围、搜索策略和可信行为评估三个问题。本文为源码与已存证据审查及下一轮设计建议；没有执行新实验，没有扩展当前后端能力，也没有更改冻结输入。

## 1. 当前结论

当前已有“冻结输入 → 完整联合候选 → 约束检查 → 真实周期行为积分 → 独立判决 → 有限反馈”的工程纵向链。距离“动态、噪声、功耗同时约束的联合分配”仍缺模型与测量闭合，以及真实 LLM 的成功调用和修复证据。

|核心问题|已有能力|尚未达到的能力|
|---|---|---|
|Block Space 与物理映射|CP 电荷、理想 RC、线性 VCO 的可执行公式；JSON 离散 choices；完整性、单位、等电流、平衡电压及轨迹域检查|通用范围合同；各 Block 的联合性能域；噪声/功耗模型；动态指标的可执行系统映射；模型误差与可信域|
|搜索与 LLM 决策|规则、网格、随机、解析相位反馈；真实 LLM 提议接口和日志|真实 LLM 成功候选及 FAIL 后修复；数值敏感度；BO；多指标折中策略的实验依据|
|行为评估与反馈|完整周期闭环轨迹、相位/频差/锁定、Vctrl；Policy 外独立验收；历史 MATLAB 数值回归|频域 BW/PM 验证；标准最终稳定时间；相噪/抖动、功耗；多初态/扰动/随机性及新域验证|

## 2. 问题一：公式在哪里，范围在哪里，如何定义

### 2.1 现有代码的实际分工

|内容|位置|语义|
|参数名、单位、指标注册|[contracts.py](../pll_allocation/contracts.py)|五 Block 全参数合同；当前固定模型版本、工况和测量协议|
|合法取值|[regular80.json](../examples/regular80.json)、[joint84.json](../examples/joint84.json)|`block_space.blocks.*.*.choices`，不是连续 min/max 域|
|候选域与耦合检查|[contracts.py](../pll_allocation/contracts.py)|`build_problem`、`check_candidate`；当前只接受声明的 CP 双向等电流耦合，并硬编码平衡电压等检查|
|CP 的 q(d) 与平衡时序|[cp.py](../pll_allocation/_legacy/physics/cp.py)|带符号电荷；q0 已含局部代理 DC 需求|
|LF 的 Z(s) 与 RC 状态转移|[lf.py](../pll_allocation/_legacy/physics/lf.py)|理想两状态 RC；Cload 加入 C1；Rload 增量导纳省略|
|VCO/Divider/PFD 的闭环数学行为|[python_behavioral.py](../pll_allocation/_legacy/evaluation/python_behavioral.py)|线性调谐、理想除 N、相位到时序转换和逐周期状态更新|
|传给策略的物理先验|[behavioral.py](../pll_allocation/behavioral.py)|`PHYSICS` 为公式说明；`screen` 只可执行预测静态相位和平衡 Vctrl|

所以“有 BlockSpace 对象”不等于“完整模块模型库已经建立”。当前执行公式、给 LLM 的公式文字和 JSON 域分散保存；尚无统一的公式注册、版本引用和模块输出依赖图。

当前常规 80 MHz 域：CP 电流 80/90/100/110/120 µA，q0=6/8/10 fC；LF Rz=3820/5000 Ω；其余 LF 参数固定；PFD 和 Divider 固定；VCO 固定。84 MHz 域才增加 f0、Kvco 的各三个选择，合成 450 个点。五个 Block 的完整输出目前不代表五个 Block 都有独立搜索自由度。

现有公式可写为：

```text
q(d) = q0 + I_up*d (d>=0)，否则 q0 + I_down*d
phi_eq_deg = -360*fref*d_eq；等电流时 = 360*fref*q0/Icp
f_vco(V) = f0 + Kvco_Hz_per_V*(V-V0)
C1eff = C1+Cload
Z(s) = (1+s*Rz*C2) / [s*(C1eff+C2)+s²*Rz*C1eff*C2]
```

### 2.2 下一版必须把两个映射分清

```text
模块独立变量 z_b + 共同工况 c
         ↓ 模块模型 m_b，适用域 D_b
模块行为参数/性能 theta_b：增益、误差、噪声谱、功耗等
         ↓ 系统模型 F + 明确的测试激励/测量协议
整机指标 y：动态、稳态、相噪、抖动、总功耗等
```

这里的 z_b 可以是行为参数或模块档位，无须引入 W/L、PDK 或在线电路表征。独立变量、派生性能、固定条件、模型有效域必须分别标识；不能把噪声、功耗、Kvco 等所有性能当作彼此无关的自由轴。

每个模型至少应记录：模型 ID/版本；独立变量的类型、单位、min/max 或 choices、步长与归一化方式；可执行公式或插值数据入口；派生性能；同 Block 联合约束；跨 Block 约束；有效工况/频段/电压/激励域；来源与 SHA；误差/不确定度；验证状态。

需要区分三个域：**策略允许搜索的域、数学模型有效的域、有数据支持的域**。声明目标可用于条件性的行为研究，但不能自动宣称电路可实现。历史 CP/VCO 电路数据主要支持局部电荷与调谐关系，当前模型卡明确没有建立联合噪声/功耗能力。

### 2.3 各 Block 下一步最低应补的内容

|Block|可考虑的独立变量/档位|须建立的派生关系及限制|
|---|---|---|
|PFD|复位/延迟或模式选择|相位/时序响应、有效频率、死区或明确理想假设、等效噪声与功耗；复位与 CP 脉冲关系|
|CP|电流、失配/电荷误差或一组联合档位|q(d,V)、噪声电流 PSD、功耗、输出电压域；电流与噪声/功耗的条件关系|
|LF|Rz、C1、C2 的合法域|精确阻抗/状态方程、热噪声、负载；若需要面积预算再定义面积代理，不扩大当前主线|
|VCO|调谐参数或联合模型档位|f(V)、Kvco、可用调谐区、相噪 PSD 与功耗的联合关系|
|Divider|N 由整机关系固定；可另选实现档位|相位除 N、附加噪声/延迟、最高适用频率与功耗；不为增加自由度而任意改变 N|

没有可信噪声/功耗数据时，可先建立来源明确、假设显式的行为研究模型域；数值系数与联合域需要单独说明依据。不得让 LLM 临时编造系数，也不能把单个历史电路锚点扩成任意组合。

## 3. 问题三：怎样补齐可信行为评估

### 3.1 当前的可信度边界

当前使用 `legacy_exact_rc_behavioral_tb_v1`，实际执行 CP 电荷脉冲、精确理想 RC 传播、线性 VCO 相位积分和反馈。它是实际运行的行为模型，不是返回预设 PASS 的桩。

但现有独立性主要是验收权在 Policy 之外；MATLAB 历史回归证明测试条件下的实现一致性。它不能证明抽象模型覆盖所有 PLL 物理现象，也不能证明未来加入的噪声/功耗模型正确。换成 MATLAB 进程本身不会增加物理可信度。

当前 Builder 仍限定 1.8 V、27°C、N=8、fref=10–10.5 MHz、40 µs、尾 50 周期、hold 20，并要求三个旧指标。正常示例不硬约束锁定时间、BW、PM、噪声和功耗。当前 `lock_time_s` 是首次满足 hold 窗口的起点，不能直接等同最终稳定时间。

### 3.2 完整 SystemSpec 先定义测量，再填写目标

|指标族|下一版需冻结的测量条件|
|---|---|
|稳态|输出频率、静态相位的符号/参考面、平均与 RMS/峰值的区别、尾窗与容差|
|锁定与动态|初始相位/频差/Vctrl；输入相位或频率阶跃的幅度和时刻；稳定误差带、连续保持或直至终点、超调和观测时长|
|频域|参考相位到输出相位的归一化闭环 -3dB 带宽，开环 unity-gain crossover 和 PM 各自定义；连续近似还是采样环路|
|噪声|每个噪声源的 PSD、单位、注入位置、相关性、工作点、适用频段、SSB/单边约定|
|抖动|输出频率、积分上下限、rms time jitter/period jitter 等类型、是否排除确定性 spur、统计误差|
|功耗|哪些 Block/缓冲器/参考源计入、静态还是稳态平均、供电与频率/活动率条件、估算或实测来源|

新建 v2 合同和案例，保留 v1 冻结案例、提取核心与历史运行。未知指标继续 UNSUPPORTED；模型超域和数值失败不转成普通可修复性能违例。

### 3.3 动态映射与验证的建议

已有旧文件 [cppll_small_signal.m](../../PLL_AGENTV2/PLL_AGENT/simulation/matlab/cppll_small_signal.m) 明确实现的是连续时间小信号近似，并说明没有采样效应。可复用其公式和设计思路，不能把原数值直接当作新采样环路验证结果。

对于锁定点附近、理想等电流 CP 的连续近似：

```text
Kpd = Icp/(2*pi)                  [A/rad]
Kv_rad = 2*pi*Kvco_Hz_per_V       [rad/s/V]
L(s) = Kpd*Z(s)*Kv_rad/(N*s)
H_ref_to_out(s) = N*L(s)/(1+L(s))
H_vco_noise_to_out(s) = 1/(1+L(s))
```

这些可作为策略的快速先验。最终 BW 用声明的闭环传递及归一化定义测量；PM 用声明的开环/断环定义测量。建议进一步对实际周期状态模型在锁定点线性化，并做相位/频率扰动注入核对；锁定与大信号稳定仍通过瞬态 TB 检查。连续近似的适用性应有频带/误差证据，不能只凭“最后锁住”判频域通过。

### 3.4 噪声与功耗的建议

先做锁定状态下的噪声传播评估，不必第一步就实现昂贵的长时间随机瞬态。每个噪声源使用与其注入位置和相位参考面对应的传递函数。若源互不相关，且使用输出处单边相位 PSD：

```text
Sphi_out(f) = sum_i |H_i(f)|² * S_i(f)
sigma_t = sqrt(integral[fL,fH] Sphi_out(f) df) / (2*pi*fout)
```

有关联时还须交叉谱项；锁定线性化、单边/双边以及 SSB 相噪换算必须一致。解析积分本身可成为明确声明的频域行为评估，但需要独立数值实现/参考算例校验，再选若干点做噪声注入交叉检查。不能让 Policy 的同一近似函数直接生成最终 PASS。

现有 40 µs 轨迹的普通频谱分辨尺度约为 25 kHz；10 MHz 参考周期采样的奈奎斯特频率为 5 MHz。因此它本身不能验证示例中 10 kHz–10 MHz 的完整抖动积分带。增加 PSD 字段或对当前短轨迹直接 FFT 都不能补齐该能力；需频域噪声模型或具有相应观测时长/采样率的噪声 TB。

功耗应由模块模型计算 `P_b(z_b,c)` 后按冻结边界求和。可以是经验证的行为功耗模型，不要求在线晶体管仿真；但只有 `P_b_max` 预算而无消耗模型，只能检查预算账目，不能验证该候选真的满足功耗。CP 输出脉冲电流也不能直接充当全部供电电流。

## 4. 问题二：搜索策略与反馈后的实际决策

### 4.1 当前已经做了什么

[policies.py](../pll_allocation/policies.py) 中规则策略按解析静态相位等排序；网格/随机枚举完整候选；反馈基线根据真实违例，优先减少解析相位违例并靠近上一候选。它不是数值敏感度搜索，也没有 BO；尤其没有已验证的动态/噪声/功耗多目标修复。

[runner.py](../pll_allocation/runner.py) 的反馈已含违例、满足项、裕量、模型问题、历史与剩余预算，但 `sensitivity_evidence` 明确是解析关系。`LLMPolicy` 能接收这些对象并决定完整新候选；现存两次真实网络请求均超时，没有实际 LLM 候选，不能称为 LLM 策略已验收。

### 4.2 推荐先实现“物理首次分配 + 有限敏感度修复”

1. 首次 LLM 只看冻结 SystemSpec、模块域、物理映射和公开先验，独立给完整候选；在第一次完整 TB 之前保存。不得先在本任务上扫 TB，再把结果叫无反馈首次分配。
2. TB 输出实际指标、归一化违例、已满足项的裕量、域问题、成本和证据位置。噪声评估再提供按源分解的贡献；功耗提供模块贡献。
3. 针对主要违例，使用解析关系提出相关变量，再做少量局部实际探测。以归一化变量 u 和有方向的归一化违例 r 构造 `J[j,i] = delta r_j / delta u_i`。
4. LLM 根据 J、预测误差、现有裕量和预算选择局部修复、跨模块重新分配、请求下一次有价值的探测或停止；每次仍交付完整合法候选并由 Runner 复验。

敏感度探测必须由 Runner 调度、计入 TB 预算。中心差分通常每个独立方向需要两次评价；等电流等耦合变量沿合法方向一起变化；域边界可用单侧差分；离散档位只报告邻域差，不能假称连续导数。q0 可为零/负值，不宜一律用对数敏感度。锁定状态等类别指标不能直接求普通导数；噪声估计的变化必须与统计误差区分。

当前 Policy 返回合同仅有 PROPOSE/STOP，没有请求探测或 BO 工具的动作。若要让 LLM 选择探测方向，需要扩展为经 Runner 校验与执行的版本化工具请求；不能把隐形 TB 调用塞进 Policy。

### 4.3 BO 的角色

约束 BO 可以建模目标/违例的不确定性，在评价昂贵时挑选下一点；可作为独立基线，也可作为 LLM 可调用的候选建议工具。参考原始方法：[Gardner 等，Bayesian Optimization with Inequality Constraints，ICML 2014](https://proceedings.mlr.press/v32/gardner14.html)。是否适合本项目，需要在相同输入/预算下验证。

当前单次 TB 保存耗时约为数毫秒、空间 30/450 点，完整枚举已经是很强的可行性参照；不能为了“更智能”先增加 BO/Agent 复杂度。扩大联合域、引入更昂贵的动态/噪声评价后，再比较 BO 是否节省实际成本。

建议对照：物理规则、随机/枚举、约束 BO、LLM 首次、LLM+相同反馈、LLM+敏感度工具。分别记录首次成功、预算内成功、到首个可行点的全部评价（含探测/失败）、裕量、LLM 成本与总时间。工具带来的收益和 LLM 决策带来的收益需要通过消融分开。

### 4.4 反馈应对应哪些决策

|反馈现象|LLM 可做的决策；均需合法性检查与重新评估|
|---|---|
|静态相位不满足|在 q0/电流可行关系内修改；检查动态、功耗和噪声的连带影响|
|稳定太慢或动态超调不满足|联合协调 Icp、Kvco、LF；用动态测量/敏感度判断，不固定为“加电流”|
|输出噪声/抖动不满足|看噪声贡献，调整带宽或噪声源档位，同时检查稳定、参考噪声传入和功耗|
|功耗不满足|定位主导模块，切换联合性能档位或重分配预算，守住噪声与动态裕量|
|局部改动方向相互冲突/预测持续失真|缩小可信邻域、追加有价值探测或转向其他合法区域|
|UNSUPPORTED/模型超域/数值异常|区分模型能力问题与性能失败；停止或提出后端/域需求，不能靠调参冒充验证通过|

表内是允许的决策类别，不是应写死的单一调整顺序。LLM 保留选择变量、幅度、局部/全局以及停止的权力；Runner 保留预算、执行和判决的权力。
