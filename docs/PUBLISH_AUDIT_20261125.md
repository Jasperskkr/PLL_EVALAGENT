## 核心调用链和消费方式

`problem + allocator → pipeline → spec_allocation → initial / RegionExplorer / 正式M1 → 独立复核与verification_handoff → feedback / 原生M2 → delivery → sizing_handoff / run_manifest`。

用户入口是 `python -m pll_allocation pipeline`。`--problem` 包含规格、六轴域、单位和固定N，`--allocator-config` 包含策略、数量目标和硬预算，`--out` 要求新目录。下游集合读取 `sizing_handoff.json.candidates`；M1交接的READY只表示可以送入M2。完整字段和迁移方法见 [输入输出合同](IO_CONTRACTS.md)。

旧阶段名文件读取脚本需要改读职责名；旧运行目录仍保留且可读取。旧模型记录可显式离线检查，但不能冒充当前模型继续执行。M1/M2、v1/v2与物理含义的phase_step保留，冻结协议/模型身份、历史出处和兼容转发不为改名而篡改。

发布前从Git暂存树导出313个维护文件，独立重建理想、相位阶跃、返回比、非理想/噪声四个后端。完整回归 **993通过、10项历史档案依赖跳过、零失败/错误**（`-W error`），架构和职责命名守卫通过；运行后维护文件摘要不变。该源码目录没有本地实验和预编译DLL。

独立源码再执行16组实际CLI，287项输入/证据/成本/交付检查通过，15组VCO导出验证来源文件字节不变。另从远端基线源码独立构建标准后端，对完全相同输入运行8组对照：nominal、tight、N4/N10/N16、更严格捕获、增强物理和噪声配置。两版的候选参数、M1/M2指标、判决、交付数量、正式调用次数和积分点完全一致；原有能力未退步。

相同输入还复现了远端的两项数值失败：低增益多项式求根无法在原固定窗口包围，默认M1频率扫描漏掉低频交越。新版在有界扩展后均返回有效结果；显式扫描界限、用户输入范围与开放调谐轨仍严格检查。数值失败不会被改成物理无解证明。

独立性检查发现新增数值回归曾读取三处未发布本地档案，现已改成固定输入参数及远端公式AST摘要校验，相关23项数值测试脱离档案通过。公式摘要忽略Python版本新增的空type_params字段，保留项目支持的Python版本兼容。文档与安装清单的混合换行统一为LF，生产数值源码仍按原字节和来源收据保护。

验收不将过程结束解释为规格全部满足：预算内允许PARTIAL或零交付；PM/jitter等标准M2未支持项保持UNKNOWN，完整SystemSpec/管级/PVT均未认证。本轮不运行真实LLM API，不以离线接口测试推断LLM策略效果。
