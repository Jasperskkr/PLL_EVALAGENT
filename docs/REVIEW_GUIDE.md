# 给研究合作者的审查说明

当前版本适合审查固定拓扑下的行为级联合分配：问题合同、物理工具、真实 LLM 决策、预算边界、M1 独立复核、真实 M2 和反馈修复。它是研究原型，不是任意 PLL/晶体管自动设计系统。

建议先运行 README 的确定性 M1 与一次原生 M2，再沿 ARCHITECTURE 阅读；审查源码无需 API key，实际 LLM 运行需自己的服务配置。

[项目章程](../PROJECT_CHARTER.md)记录当前实现、真实验收和研究边界；[逐文件导读](CODE_MAP.md)解释共享代码及其主线、可选或兼容职责；[职责命名](NAMING.md)列出迁移及保留旧合同的边界。新增多策略的配置、状态和公开复现命令见 [Spec Allocation](SPEC_ALLOCATION.md) 与 [RUNNING](RUNNING.md)。

## 七个审查问题

1. 改变 Spec 和六轴范围后，问题绑定、反解、采样、优化是否都采用当前输入？
2. 反解/正向模型是否遵守拓扑和适用域？同模型回代是否被误称独立准确度？
3. LLM 是否根据真实 Observation 改变动作？非法提案和 Provider 失败是否留档？
4. 校准、失败、有限差分、最终复核和 M2 posthoc 是否真实计费？缓存是否冒充新测量？
5. 最终参数、M1、M2、协议与模型是否绑定同一候选？
6. PM/jitter 未支持、条件捕获和数值不确定是否保持正确状态？
7. 确定性和 LLM 对照是否具有相同工具、反馈机会、硬预算和失败计费？

多点交付另检查：`target_count`（初始 M1 池）和 `m2_target_count`（原生联合通过点）是否区分；首个通过后是否继续；`sizing_handoff.json` 是否只含质量与距离达标的真实联合通过点；预算不足是否报告 PARTIAL。成功补点不得伪造失败，SLSQP/Sobol/反解等所有来源都必须先排除已交付近邻，再判断是否达到补点目标。TEST 通过点不进入正式交付，PM/jitter UNKNOWN 不变。

## 能力与差距

|当前实现|尚未证明或建设|
|---|---|
|用户连续域与多项规格|任意规格集合和任意 PLL 拓扑|
|物理反解和正式 M1|整个范围的可行性认证|
|真实 LLM/M2 反馈闭环|未见场景的大样本稳定修复率|
|完整候选和成本记录|LLM 比确定性策略更快、更可靠|
|M2 BW/条件捕获|周期 PM、完整 jitter/power、多工况认证|
|六参数联合点与可选VCO guidance/实测反馈合同|真实器件开发、其他模块合同及跨工况可实现性认证|

当前共享版不含实验数据，因此不提供可由本仓库独立核验的效率排名和成功率。代码能力、mock 测试和真实研究成绩必须分开。

## 后续研究建议

优先固定现有模型及可测指标，对同一真实失败初始点比较等预算的确定性反馈与 LLM 反馈，报告联合通过率、修复率、首次联合可行耗时、完整 M2 次数、最差裕量和全部失败成本。使用冻结的新测试问题，不能把已看过的场景当作未见。

重点关注 M1 均可行但 M2 不同的增益分解、f0/调谐点，以及当前按 M1 裕量选择新点是否遗漏动态更好的点。引入局部偏差估计/历史记忆时需绑定模型、协议和适用域。

已有可选 [VCO合同](VCO_SIZING_CONTRACT.md) 支持guidance、实测反馈及回填再验证输入；审查时检查源候选、原用户约束、实测条件及目标点精度。后续接入真实模块开发和不可实现反馈。当前不引入 PDK/MOS/sizing 运行依赖；完善模型不是先研究反馈策略的前置条件。
