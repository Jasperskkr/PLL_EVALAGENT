# 项目与工作流图对应审计：Block Space Model / Verifier

审计日期：2026-11-06（Asia/Shanghai）。对象为当前工作树，包括已有Stage5未提交接口和上一轮关系图谱；不把历史冻结提交当成全部现状。

## 结论先行

项目已经具备图中“输入规格→参数空间与物理先验→完整候选→真实行为TB→结构化反馈”的主干。当前准确定位是：**在人工声明的六维理想PLL行为参数域内，用连续小信号M1帮助分配，再用事件行为M2独立测量受支持的系统指标。**

当前最大的收敛障碍依次是：必需指标的独立认证不齐全；模型准确性只在有限范围和具体点获得支持；图中的模型误差反馈与验证反馈还没有形成可运行的自动维护闭环。LLM目前的研究角色主要是选确定性数值工具和候选句柄，真实LLM反馈修复没有接入正式Policy。

因此，Block Space是一个可执行、可追溯的行为研究模型，Verifier也确实运行开关/边沿行为过程并从波形测量。其已证实的能力需要按“模型假设、测量定义、参数点与工况”理解。当前完整SystemSpec认证通过为0，与源码的保守判决一致。

本轮读取48份关键来源，校验5份上游MATLAB公式源及原Python事件函数快照，全部SHA匹配；复核一份真实Baseline的版本/候选/结果绑定。针对性复验85项既有测试通过。本轮没有新完整M2实验、外部LLM或MATLAB运行；历史实验次数不重计。

## 2. Block Space Model究竟怎样建成

### 2.1 原始材料与构建步骤

构建链可以复原为：

1. 从已有MATLAB v3.4理想CPPLL工程审查频率计划、线性VCO、两电容无源LF、连续环路核及交越定义。
2. 在Stage1输入中人工规定研究频率、六个变量范围/离散值、零非理想条件和目标BW/PM。名义值沿用参考工程，但新组合的能力性质是声明目标。
3. `tools/prepare_block_space_v1.py`读取Stage1 JSON和41行语义CSV，生成Stage1.5正式模型快照：变量角色、单位、来源、范围理由、拓扑、7条联合关系、公式注册和校准记录合同。
4. `block_space/contracts.py`执行模型冻结校验与候选域检查；`physics_mapping/model.py`执行M1正向计算。
5. 以不同数值求根、KCL、有限域扫描和稀疏事件模型核对实现与局部行为；后续Stage4.1/5补充具体点的M2证据，保留旧快照不回写历史。

原公式注册的5个唯一MATLAB源文件——`solve_tuning_point.m`、`vco_model.m`、`pll_linear_kernel.m`、`loop_filter_model.m`、`characterize_loop.m`——本轮均仍可读且SHA与注册一致。这证明来源完整可追溯，不等于本轮执行了MATLAB。

### 2.2 输入空间是什么

17个输入包括6自由变量、4固定条件、7理想假设。41项语义目录还包含派生量、系统指标和历史上下文；41不代表41个可优化旋钮。

|块|可分配变量及原范围|实际含义|
|---|---|---|
|CP|Icp=50–200µA|理想对称UP/DOWN脉冲幅值，不是总供电电流；不含功耗/噪声/输出顺从范围模型。|
|LF|Rz=2–8kΩ；C1∈{50,100,200}pF；C2∈{0.5,1,2}nF|C1对地，并联串联Rz–C2支路；理想R/C，电容选择是离散的。|
|VCO|f0=60–76MHz；Kvco=10–40MHz/V|f0为0V截距，Kvco为Hz/V；改变二者是声明新的行为目标，不是已测振荡器能力。|
|PFD|无自由性能轴；reset=0|理想边沿状态机；没有独立死区、reset、延时和噪声预算。|
|Divider|N=8固定|理想整数分频；没有独立延时、抖动、功耗预算。|

另外固定fref=10MHz、控制轨0/1.2V；Kvco2、CP mismatch/leakage、q0、PFD reset、Cload/Gload全为0。非零非理想会被parse_parameters明确拒绝为UNSUPPORTED。1.2V是控制范围，不能据此推导整机供电或功耗。

范围来源在JSON中直接写为`MANUALLY_DECLARED_BEHAVIORAL_EXPERIMENT`，生成脚本也逐项给出了围绕名义点的局部探索理由。没有训练过程、回归拟合、PDK表征或自动发现这些范围的步骤。当前研究目的与这种建模方式相容，但“域内”只能表示进入研究模型允许的候选集合。

### 2.3 公式怎样从参数得到系统指标

用F=N·fref、G=Icp·Kvco/N、s=j2πf：

- 静态调谐：Vreq=(F−f0)/Kvco，要求0<Vreq<1.2V。
- PFD/CP平均小信号增益：Kpfd=Icp/(2π) A/rad。
- VCO角频增益：2πKvco rad/s/V。
- LF阻抗：Z(s)=(1+sRzC2)/(s(C1+C2)+s²RzC1C2)。
- 环路：L(s)=G·Z(s)/s；归一化闭环T=L/(1+L)，参考到输出相位为N·T。
- UGF：|L|=1的唯一向下交越；BW：|T|=1/√2的唯一向下交越；PM：UGF处180°+arg L。

M1默认扫描8000个对数频点，找到交越后在log频率上二分。它在假定已锁定、内部工作点和连续小信号条件下求频响，不积分捕获过程。返回80MHz来自频率计划与调谐存在性，不是观测到一次瞬态确实达到80MHz。

`PLL_EQUATION_REGISTRY_V1.json`保存公式和来源目录；实际执行公式写在Python函数中，运行时没有把注册表解析为符号求解器。`allocation.physics`又提供同物理关系的快速多项式求根、条件反解和必要约束传播。三个层次必须区分：公式索引、正式M1执行、分配器的廉价求解工具。

### 2.4 “可行域”目前有几层

1. **声明域**：六轴原范围/离散选择的笛卡尔积。
2. **模型有效域**：声明域内再满足单位、正值、理想假设、严格内部调谐和数值条件。
3. **M1规格可行域**：再满足BW/PM及条件频率目标。
4. **M2完整认证域**：具体候选的全部必需指标经可信独立测量通过。目前未建立该完整域。

例如f0=68MHz、Kvco=10MHz/V都在各自范围内，但需要Vreq=1.2V，M1把它视为rail而拒绝。PM≥50°也不是逐轴范围可保证：C2/C1至少6.548632，九种电容对有三种完全不满足该必要形状条件。

上一轮总表补充了给定电容/形状后BW、Rz与IcpKvco的条件交集，并做M1重建核验。该图谱是只读研究产物，没有改变正式Agent的上下文或Solver调用链。

## 3. Verifier究竟怎样建成

### 3.1 来自哪里，和M1独立在哪里

当前正式Verifier由原Python `python_crosscheck.py::simulate`的边沿/Euler过程翻译成C++，加上相位激励和原始观测；Python负责参数校验、激励实验、原始轨迹保存、指标提取、收敛和最终判决。原函数字节快照与上游文件本轮SHA均一致；编译DLL与当前kernel.cpp的身份绑定检查也通过。

M1与M2使用相同的理想块语义，但求解方式不同：M1计算连续平均小信号传递函数；M2逐步处理PFD边沿、CP脉冲面积、LF状态、电压限幅、VCO相位。测量阶段不调用M1传递函数填充结果。全部事件频响完成后，才在`comparison_after_measurement`调用M1做差值对照。

独立性有明确层级：

- **与候选预测独立**：Verifier不信任Proposal自带M1；测试中篡改Proposal预测也不改变实测判决。
- **数值实现独立**：M2事件积分与M1频域扫描不同，能观察rail、初值和捕获问题。
- **测量独立**：BW由注入响应/原始波形拟合得出，扫频细化取实测交越括号，不使用M1的BW作为答案。
- **物理假设仍共享**：相同理想CP、线性VCO、理想RC、零reset/非理想。M2不能揭示两者都没有建模的噪声/功耗/器件限制。共享参数parser也意味着它不是第二套独立单位合同审查。

这符合行为级研究主线；后续可信度建设应优先加强行为工况、测量定义和数值覆盖，不要求把PDK/ngspice引入本项目。

### 3.2 内核每一步具体做什么

`kernel.cpp`中的状态为v=Vctrl、u=第二电容节点电压、φ=VCO相位及PFD的up/down两个布尔状态：

1. 由f=f0+Kvco·v得到本步VCO频率，参考相位允许正弦调制。
2. 检测参考/分频相位是否跨过下一个2π边沿，在固定步长内用分数插值求边沿位置与先后顺序。
3. 参考沿置UP，反馈沿置DOWN，两者同时为高即理想reset；积分步内各段的UP−DOWN，得到平均CP电流。
4. 按KCL积分：C1·dv/dt=iCP−(v−u)/Rz，C2·du/dt=(v−u)/Rz，采用显式Euler；Vctrl在0–1.2V限幅并统计clamp。
5. 用本步频率积分φ，并记录连续分频相位、输入相位、两节点电压、clamp计数和参考/反馈边沿时间。

它是“固定时间步长内带边沿插值的开关行为积分”，具有Euler误差和单步边沿数限制。Python在运行前检查dt·LF最快速率及dt·参考/反馈频率上限，并检查激励单调性/采样分辨率；缺DLL、身份不匹配或数值失败明确报错，没有伪造回退。

### 3.3 每次完整TB包括两类实验

**冷启动捕获**：默认v=u=0.15V、初始VCO相位0，运行160µs，dt=0.4ns与0.2ns各一次。按10个参考周期组成1µs观测块，块内检查频差≤100ppm、wrapped相位峰值≤5°、控制变化≤5mV、无clamp、无块内cycle-slip；尾部至少连续10块有效才标记窗口内捕获。锁定时间是末尾持续有效序列的起点，1µs分辨率，并比较两步长频率/电压/锁定时间差。

**暖启动小信号BW**：每个频点从静态调谐电压Vreq启动，不继承冷启动波形；预留稳定时间后向参考相位加入正弦。原频率网格10kHz–1MHz；必要时加5/2kHz低频锚点，再用实测−3dB交越区间的几何中点细化。四组实验分别为：基准0.01rad、半幅0.005rad、半步长、双测量窗。默认丢弃至少40µs或8个周期，再测12个周期，双窗变体测24个周期。

四套频响加两次捕获构成一次“完整M2评价”；每套扫频包含很多原生仿真。真实Baseline一次为106次native，不是只有一条瞬态。这个成本在结果中单独计数。

**重要区别**：从Vreq启动测得局部BW，并不能证明从0.15V能捕获；从0.15V在160µs内捕获，也不能证明任意初始状态全局可捕获。两类结论分开保存是当前架构的合理之处。

### 3.4 指标怎样从波形测量

响应拟合使用offset+线性trend+f、2f、3f的sin/cos最小二乘，输出分频相位基波除以参考相位基波，得到已经归一化的复数T。测量质量检查采样密度、非有限值、THD、半窗变化、拟合残差、相位误差、clamp和注入前锁定状态。

BW采用唯一向下|T|=1/√2交越，保留实测频率括号。半幅/半步/双窗差异通过门限后，将各变体的交越括号与变体间差异组成数值包络，再与规格区间比较。包络完全落入规格才PASS，完全在规格外才FAIL，跨边界为UNKNOWN。该包络只覆盖所做数值复核，没有覆盖连续相位观测与edge-only观测之间的系统定义差异。

频率由末尾分频相位斜率反推；锁定时间/电压/相位峰值来自捕获块。局部返回比与阶跃扩展另有协议和证据标签，不能填入原正式PM槽位。

## 4. 用一份真实候选串起来

读取主线归并后的真实解析Baseline，而非新增执行：Icp≈104.4043µA、Rz≈3.048125kΩ、C1=50pF、C2=2nF、f0≈63.761604MHz、Kvco≈27.063993MHz/V。

- M1：Vreq=0.6V，BW=225000Hz，PM≈72.247210°，满足当前M1目标。
- M2：从0.15V启动，窗口内捕获，lock time约33µs；实测BW=226403.934472Hz，数值包络约[226283.009338,226503.682288]Hz，BW PASS。
- 频率约79999999.99990459Hz，经验包络约±0.01Hz；不够认证1µHz，UNKNOWN。
- 正式PM=null/UNKNOWN，不能用M1的72.247°代替。
- 因此整体UNKNOWN，Pipeline标签M2_PARTIAL_PASS，verified_joint_block_spec=false。

这说明“模型会给出一个好候选”“TB实际测得BW通过”和“全部系统规格已独立认证”是三层不同结论。Stage5主策略31次完整M2均保留这种逐项判决，完整认证通过数0。

## 6. 需要重点收敛的发现

### A. 验收合同与Verifier支持存在硬缺口（最高优先）

频率1µHz和PM是当前必需目标，Verifier却明确不能给PASS，`pipeline_contracts.check_result`还会拒绝伪造这两项PASS。完整绿色出口因此在现版本不可达。这是公开、保守的能力限制，不是随机多搜几次就能解决的问题。

对应证据：`verification/verify.py:104`的PM=null、`:112`严格频率说明、`:118`三值总判决；`pipeline_contracts.py`结果检查拒绝未支持认证。

建议：优先为每个目标冻结“定义/观测量/工况/容差/不确定度/支持状态”，然后决定补齐测量还是经用户批准建立新的研究规格版本。不得静默改原容差或把局部PM诊断直接升级。

### B. Block Space目前的范围依据是研究声明（解释必须统一）

该空间适合研究联合分配的物理关系，现有证据支持其在有限理想点的用途。若目标是图中“模型是否准确”，需要分别回答公式是否正确、数值是否正确、与事件行为是否一致、在哪个参数/初值域可信。不能用一项PASS概括四个问题。

建议：保留原声明域，另建带参数点/工况/协议和源版本绑定的验证覆盖层、误差证据层。未来若研究理想模型以外的可实现性，必须另立任务，不将其混入当前行为主线。

### C. 反馈的接收、修复、学习应分别标记

确定性设计修复已运行；真实LLM修复、模型自动校准、验证自动复测均缺实现或验收。图上三种箭头应标“已运行/证据维护/待实现”，避免仅凭框图理解为已完成自主闭环。

建议：设计失败用①；可靠测量与预测有差异时进入②的偏差审查；测量本身不可靠进入③复测。未先排除单位、定义、采样与数值问题，不修改模型。

### D. 当前知识分散于几个不同层次（维护优先）

冻结模型的metric_support保留Stage1.5历史状态；Stage4.2 Registry和Stage4.1 Confidence记录后续支持；实际Agent仅读取简化轴表及allocation.physics.RELATIONS，不自动消费这两份研究索引或上一轮atlas。由此阅读不同文件会看到不同时间点的能力。

建议：在冻结资产之上构建一个只读、版本绑定的“当前能力与证据视图”，供报告和Agent查询，保留旧快照。该视图的字段必须标明是否参与实际约束/求解/测量，不能只新增更多描述文件。上一轮atlas可作为变量关系展示输入，不能直接取代执行函数。

### E. 验证协议与代码常量的对应需要显式核对

协议JSON与函数默认值/调用参数共同规定初值、时间窗口、步长、网格和质量门限；例如0.15V初值及160µs捕获窗口来自verify函数参数，不能归因于JSON。部分函数还使用固定80MHz/10MHz×8、0.4/0.2ns、1µs block等字面常量。当前固定场景相互匹配，但未来改协议或扩频率计划时，不能认为改一份JSON就完成适配。

建议：先保留原版本，把“协议字段→执行设置→观测/判决”关系作为审查合同；协议升级时检查实际执行与请求快照一致，并对不同观测量单独标定。不把同一套理想物理的两种实现称为完全独立物理真值。

## 7. 向这条研究主线收敛的具体顺序

以下是建议，**本轮没有实施或批准新的规格/协议/策略变更**。

1. **统一研究问题和输出等级。**在原图的菱形加UNKNOWN。对现有全目标使用当前保守判决；BW子集结果明确为子集研究结果。明确每个Block当前能分配的量及固定假设。
2. **收束模型合同。**把范围来源、公式适用域、联合耦合、M1计算、已验证点/工况、未验证区域汇成一个可查询当前视图；模型数据、求解器和证据保持角色清楚。
3. **优先补Verifier与规格的对应。**严格频率的不确定度及PM定义/认证是完整出口的前置缺口。先明确物理问题是否可在当前行为研究范围内认证，再开发测量，不能靠更强Agent绕过。
4. **先使三类反馈分流可审计。**①候选修复；②可比的预测误差记录与新版本候选；③固定预算内可执行的复测计划。②③开始可以是人工审查或确定性维护，不要求一开始都交LLM。
5. **最后做Agent增量实验。**在所有方法共用模型、Verifier、规格与预算条件下，比首次完整可行率、修复效率、代价和裕量；真实LLM选择工具的价值与LLM改变设计的价值分别测量。

这条顺序保持SystemSpec→JointBlockSpec→真实行为TB→Verified JointBlockSpec为唯一交付链，并把三个核心问题分别落在可检查的证据上。
