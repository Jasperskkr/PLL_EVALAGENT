# Stage 6A — Multi-Spec Joint Allocation Feasibility

## 0. 任务背景与总体目标

本项目已完成 Stage 1–5，现有统一 PLL Spec Allocation 框架包括：

* Block Space Model：六参数 CP/LF/VCO 联合设计空间；
* M1 Physics Mapping：物理预测、约束传播、数值反解；
* Allocation：Analytical Solver、Sensitivity Optimization（SLSQP）、LLM 工具编排和确定性 Repair；
* M2 Behavioral Verification：事件级 CPPLL 行为仿真与性能测量；
* Unified Pipeline：从 SystemSpec 到 Joint BlockSpec、M1/M2 验证和结构化反馈。

Stage 5 已完成不同 BW/PM 规格下的端到端探索实验。Analytical Solver 在四个 M1 可行场景中均生成了满足 M2 BW 测量要求的首次候选，但尚未充分验证非平凡的多指标联合约束、行为反馈增量价值以及模型全域适用性。

本阶段的目标不是重新设计系统，也不是立即实现 LEDRO/AutoSizer 式双层 Agent。

**本阶段核心任务：基于现有 M1/M2，研究六参数 Block Space 对多个 SystemSpec 的可分配性，运行一轮最小联合分配实验，判断现有模型是否足以支撑后续真正的 Multi-Spec Allocation。**

请优先复用已有代码、物理映射和验证协议。

## 2. 审查现有 M1/M2 的多指标表征能力（P0）

请先审查现有代码，而不是直接编写新模型。

建立一份 `Spec Capability Matrix`，至少分析：

* Bandwidth（BW）
* Phase Margin（PM）
* Unity Gain Frequency（UGF）
* VCO Tuning / Operating Point
* Conditional Capture / Locking Time
* 现有接口中的其他 SystemSpec

对每项指标明确：

1. 是否存在有效的物理映射？
2. 是否可直接解析反解、数值求解，还是主要依赖行为仿真？
3. 当前 M1 能否计算或预测？
4. 当前 M2 能否独立测量？
5. 当前指标可作为正式约束、研究级约束还是仅作诊断？
6. 模型的适用条件和已知失效风险是什么？
7. 是否有必要为了本轮实验补充模型？

特别注意：

* BW 已有 M1/M2 实验基础；
* PM 的 M1 预测可以参与研究级联合约束，但不能将 M2 局部 PM 测量误称为严格周期系统 PM 认证；
* Conditional Capture 必须检查其定义、初始条件及测量协议；
* 尚无可信模型的 Jitter、Power 等指标不得虚构预测值或 PASS。

输出审查结果，判断当前模型究竟能够支持哪些多指标联合分配组合。

## 3. 分析六参数 Block Space 的联合可分配性（本阶段重点）

沿用现有冻结 Block Space：

`x = [Icp, Rz, C1, C2, f0, Kvco]`

不得随意扩大参数范围或修改原 PLL 拓扑。

利用已有 Stage 4.2 Physics Mapping Registry、M1 物理模型和参数扫描能力，研究：

### 3.1 参数与性能耦合

分析六个参数对以下指标的影响：

* BW
* PM
* UGF
* VCO 调谐条件
* M2 可支持的捕获相关指标

特别分析：

* Icp 与 Kvco 的环路增益耦合；
* Rz、C1、C2 对 BW/PM 的联合影响；
* 不同离散 C1/C2 组合之间是否存在有效的性能权衡；
* f0 和 Kvco 的调谐约束；
* 当前六参数是否存在明显的冗余或等效自由度。

优先复用解析关系、现有灵敏度工具与确定性参数扫描。

### 3.2 联合可行域预测

建立当前 M1 可计算的联合约束集合：

`F_M1 = {x in BlockSpace | BW、PM、Tuning 等 M1 约束同时满足}`

不要求本阶段求得完整精确的六维可行域。

可以通过：

* 物理必要条件筛选；
* 离散参数枚举；
* M1 正向计算；
* 局部敏感度分析；
* 已有 Analytical Solver / SLSQP；

获得具有代表性的预测可行区域和候选。

需要保留多个不同物理组合的候选，而不是只保留一个最大 PM 解。

### 3.3 分析输出

至少回答：

1. 当前六参数能否形成有意义的 BW–PM 约束权衡？
2. M1 可行候选主要集中在哪些电容组合和环路增益区域？
3. 不同参数组合是否可能实现相近 BW/PM，但具有不同调谐或捕获行为？
4. 是否存在 M1 预测可行但接近约束边界的候选？
5. 当前 Block Space 是否过于简单，导致 Analytical Solver 已经足以解决大部分联合分配问题？

不要为了证明联合优化复杂而人为制造不符合冻结模型的物理关系。

## 4. 构造最小多指标联合分配实验

基于上述分析，设计三组递进实验。

### E0：基础联合分配

指标：

* BW
* M1 PM
* VCO Tuning

目标：

验证现有 Analytical Solver / SLSQP 能否直接找到同时满足多个 M1 约束的 Joint BlockSpec，并通过 M2 BW 测量。

### E1：联合约束权衡

在已有参数域中寻找一组实际存在约束竞争的 BW/PM/Tuning 研究场景。

目标：

检查分配器是否需要在多个参数或物理组合之间进行联合协调，而不是只调整 BW。

场景必须通过前置扫描选择并在正式实验前冻结，不得事后随意调整阈值以得到预期结果。

如果现有模型确实不存在明显的约束权衡，请如实报告，不要强行构造。

### E2：行为依赖的联合分配（有条件执行）

指标：

* BW
* M1 PM
* VCO Tuning
* Conditional Capture / Locking Time

先审查捕获测量协议和重复性。

若当前 M2 支持有效的条件捕获测量，则研究：

相近 M1 BW/PM 的不同 BlockSpec，在 M2 中是否具有不同捕获行为？

能否找到 M1 预测联合可行、但 M2 某项行为指标不满足要求的候选？

如果存在这样的案例，尝试利用现有确定性优化或反馈修复方法重新分配。

每次修复后必须重新检查全部已纳入的联合约束。

特别回归 Stage 5 中 S3 / Random seed 11 的反例，确保 BW PASS、M1 PM FAIL 不会被报告为联合分配成功。

如果现有 M2 不足以可靠支持此项实验，保留 E2 为受限探索，并报告缺口，不得通过修改测量定义或虚构约束结果获得成功。

## 5. 最小计算成本与保真度分析

本阶段不单独开发仿真加速器，但必须记录：

* M1 单点评估时间；
* M2 对应性能测量时间；
* 完整 M2 验证时间；
* M1 与 M2 的 BW 预测偏差；
* 不同区域中预测与测量 PASS/FAIL 是否一致；
* 每个联合分配候选的总评估成本。

注意区分 M2 单项测量与包含多次仿真的完整 Pipeline 开销。

优先利用 M1 进行较大范围的低成本分析，M2 只验证少量代表性候选。

初始阶段先选约 4–8 个代表性 M2 候选；如需扩大预算，必须说明原因。

本阶段不需要大量真实 LLM API 调用。

不要未经计时就宣称 M1 已实现某个具体倍数的加速，也不要将 M1/M2 一致性等同于对真实晶体管级电路的保真度保证。

尽量沿用当前统一工程架构。

优先增加独立的研究配置、分析脚本、测试和结果报告。

允许最小范围修复现有联合约束判决缺陷，但不得：

* 重写整个 M1 或 M2；
* 修改原生 PLL 方程以迎合实验结果；
* 更改原有冻结 SystemSpec；
* 降低已有测试严格程度；
* 删除历史失败证据；
* 改造为新的并行 Agent 系统；
* 直接引入完整 BO/TuRBO 或新 LLM Region Planner。

所有研究场景、参数、随机种子、模型版本及测量协议均需记录。

若必须修改核心模块，先说明必要性，保持兼容，并提供相应回归测试。

请按以下顺序执行：

6. 运行必要的测试和代表性 M2 仿真。
7. 输出完整实验结果、差异及下一阶段建议。

研究结束后，保留原始数据、失败案例、日志和可复现配置。

本阶段不自动合并 `master`。

**最终验收重点不是新增多少代码，而是清楚证明当前 M1/M2 在什么约束组合下能够合理分配、哪些边界条件下会失效，以及还缺少什么能力。**

如果现有六参数空间不足以产生有意义的多指标权衡，请直接给出该结论和物理原因。这同样是有效的研究结果。
