# Stage 4.1 — Engineering Validation of CPPLL Physics Mapping Using Behavioral System TB

## 0. 角色与任务定位

你是资深 PLL 系统设计专家、混合信号行为建模专家、验证方法研究员和科学计算工程师。

请基于现有 PLL Allocation 统一主线、Stage 4 的 M2 局部 UGF/PM 测量成果，以及 Stage 4.2 的 Physics Mapping Readiness Audit，开展 Stage 4.1 研究。

### 核心研究问题

**对于当前固定拓扑的 Integer-N CPPLL，M1 预测得到的 BW、UGF、PM 是否能够在明确的模型假设与参数范围内，可靠地指导 Joint BlockSpec 分配，并预测 M2 事件级闭环的动态表现？**

本阶段重点验证：

1. M1 与 M2 的局部频率响应是否一致。
2. M1 预测的稳定性变化是否能在 M2 的独立时域闭环扰动实验中观察到。
3. 这种一致性在不同 CP/LF/VCO 参数组合下能保持到什么程度。
4. 在哪些条件下，当前映射可能误导 Agent。
5. 能否形成有适用范围、有测量证据的工程级 Mapping Confidence。

本阶段不是重新构建 PLL 模型，也不是追求对任意周期时变 PLL 的严格稳定性定理。

最终目标是让 Spec Allocation 能够可靠利用现有物理映射，而不是得到一组好看的 PM 数字。

## 2. 冻结研究对象及边界

### PLL 模型

本阶段继续使用现有：

* Integer-N CPPLL。
* fref = 10 MHz。
* Divider N = 8。
* 固定被动 Rz/C1/C2 Loop Filter。
* 理想对称 CP/PFD。
* 线性 VCO。
* Vctrl 约束 0–1.2 V。
* 六个正式可分配参数：Icp、Rz、C1、C2、f0、Kvco。

保持：

* M1 核心方程不变。
* Block Space v1 不变。
* 原 M2 事件级物理更新方程不变。
* SystemSpec 快照及约束不变。
* 原 Protocol 1.1 不变。
* Stage 4 频响测量方法及历史数据不被覆盖。
* 现有 Agent 算法不变。

Stage 4.2 已明确，当前运行快照的 SystemSpec 包含：

* 输出频率 80 MHz 及既有严格频率容差。
* BW 150–300 kHz。
* PM ≥ 50°。

UGF 为诊断量；RUR、Static Phase Error、Locking Time、Jitter、Power 均不得自行新增为当前正式硬约束。

同时保留原 SystemSpec 的 draft 元数据，不将运行快照误称为最终产品规格。

本阶段不增加晶体管级模型、PDK、噪声、功耗或 CP 非理想参数。

## 3. Task A — 定义清晰的验证目标和判据

研究开始时，必须明确区分三个层次。

### A1. 物理预测准确性

M1 输出：

* BW_M1。
* UGF_M1。
* PM_M1。

用于预测当前理想模型下的局部环路动态。

### A2. 局部频率响应测量

复用 Stage 4：

* Series Injection。
* Direct Port / Clamp Injection。
* 复数返回比提取。
* UGF / 局部 PM 诊断。
* 数值收敛与谐波/侧带检查。

不得重新使用 M1 公式来制造 M2 结果。

### A3. 独立闭环动态证据

在真实 M2 事件级闭环中施加扰动，直接观察：

* 是否保持或恢复锁定。
* 是否产生明显振铃。
* 振铃是否衰减。
* 超调和峰化程度。
* 恢复时间。
* 是否出现周期滑移。
* 是否发生 Vctrl 限幅或异常漂移。

注意：

**闭环稳定性实验可以支持局部 PM/UGF 映射的工程适用性，但不能直接证明完整周期系统的严格 PM 数值。**

不得通过时间响应的某个单一超调量直接反推 PM，并称为独立 PM 测量。

正式研究协议应预先声明：

* 激励幅度。
* 测量时间窗口。
* 收敛性条件。
* 振铃/衰减分析方法。
* 工程一致性判断。
* UNKNOWN 和失败处理规则。

不得根据最终结果倒推通过门限。

## 4. Task B — 开发独立 M2 闭环扰动实验

这是本阶段的 P0 任务。

### B1. 锁定工作点初始化

对每组合法 BlockSpec：

1. 使用现有模型确认理论调谐电压。
2. 在锁定点附近初始化。
3. 运行未加扰动的 M2 闭环。
4. 检查实际平均 Vctrl、频率和相位误差。
5. 确认控制电压没有触轨、漂移或异常周期滑移。

如果工作点不满足预先定义的稳态有效性条件，应返回明确的失败原因。

不得在不稳定的工作点继续计算所谓的小信号稳定性指标。

### B2. 参考相位扰动

在锁定状态下施加小幅参考相位变化。

初步建议：

* ±0.01 rad。
* ±0.02 rad。
* 有限上升时间的平滑相位阶跃。
* 时间步长 0.4 ns / 0.2 ns。
* 至少两种观测窗口。

这些是初始实验建议，正式数值应在首次实验前固定。

必须使用真实输入相位轨迹进行对照，不得把有限上升时间的激励误认为数学上的理想瞬时阶跃。

注意区分：

* Phase Step Response。
* Frequency Step Response。
* Cold-start Locking Response。

本阶段主要研究第一种，不得把局部相位扰动后的恢复时间称为 Cold-start Locking Time。

### B3. 测量输出

保存实际时域数据：

* Reference Phase。
* Divided VCO Phase。
* Unwrapped Phase Error。
* Control Voltage。
* Instantaneous Output Frequency。
* PFD UP / DN State。
* CP Charge。
* Cycle-slip Events。
* Saturation / Rail Events。

从这些轨迹中计算：

* Peak Phase Deviation。
* Overshoot / Undershoot。
* Ringing Amplitude。
* Ringing Decay。
* Settling Time。
* Residual Phase Error。
* Lock Retention / Recovery。
* Measurement Validity。

指标的定义、相位展开规则、滤除参考周期纹波的方法和观测时间必须明确。

如果无法稳定提取振铃或衰减率，不得输出虚假的数值。

### B4. 可选的独立扰动

如参考相位扰动仍不足以检验关键环路状态，可增加一次小幅 LF 控制电压初始扰动。

该实验应明确标为不同扰动类型，不与参考相位阶跃结果混为一谈。

不得要求 C07 必须失锁或发散才算实验成功。

* M1 认为相近的环路响应，M2 是否仍然相近？
* CP 脉冲、VCO 调谐位置或事件行为是否带来差异？
* 当前 M1 是否遗漏了与参数拆分有关的重要行为？

这项实验尤其有助于判断现有 Block Space 的物理映射是否只是对组合增益有效。

C09、C10 必须保留为独立测试点。

冻结分析协议后，再运行 C09/C10。

任何根据 holdout 失败结果进行的改进，必须标记为下一轮研究，不得将同一 holdout 重复用作无偏最终验收。

## 8. Task F — 研究是否足以支持首次 Spec Allocation

本阶段不开发新的 Agent 算法，但必须分析结果对 Allocation 的实际价值。

例如：

### 情形一：M1 与 M2 局部频响一致，闭环动态也符合预期

结论：

现有物理映射在已验证区域得到工程行为支持。

建议 Agent 优先使用 M1 进行快速分配，无需每次都运行完整 M2。

### 情形二：局部频响接近，但闭环动态明显异常

结论：

当前映射存在未被充分描述的行为风险。

进一步诊断：

* 采样与周期效应。
* 非线性动态。
* 参数域风险。
* 工作点初始化。
* 数值测量问题。

不能直接将问题归咎于 M1。

### 情形三：只有靠近规格边界的候选存在歧义

结论：

研究是否应引入暂定安全裕量、额外 M2-Fast 筛选或边界复验。

任何裕量必须标为待验证的策略假设，不得根据少数案例宣布全域安全保证。

### 情形四：M1 与 M2 在多数合法候选上显著不一致

结论：

当前 Physics Mapping 的可信适用域不足，需要研究模型假设或验证方法。

不得为了改善一致性自动修改 M1 方程。

最终需明确回答：

**当前 M1 是否足以支撑在既有 Block Space 中寻找候选？在什么区域可以放心使用，在什么区域需要 M2 提前参与筛选？**

## 11. 验收与结束条件

本阶段的成功不以所有候选 PASS 为标准。

至少需要满足：

**A. 可执行性**

已有 M2 事件级闭环可以在锁定后接受相位扰动，并记录完整有效的动态响应。

**B. 测量可信性**

扰动幅度、时间步长、测量窗口和拟合方法经过收敛性检查。

**C. 映射区分能力**

C04/C05/C06、C07、C01/C08 等配对实验能够提供可解释的行为对照，支持或反驳相应 M1 预测。

**D. 独立验证**

C09/C10 在固定方案下完成 holdout 检验，不能利用其结果事后优化同一轮判据。

**E. 工程结论**

能明确指出：

* 哪些 M1 映射获得工程行为支持。
* 支持的具体范围是什么。
* 哪些区域有风险。
* 哪些指标仍然 UNKNOWN。
* 是否值得增加 M2-Fast 参与前端分配。

**F. 兼容与保护**

既有正式 M1、Block Space、SystemSpec、Agent 和 M2 回归未被破坏。

记录完整 Git 状态、阶段提交及审查包 SHA，不伪称未提交成果已经冻结或合并。

## 12. 最终汇报必须回答的七个问题

1. **WHAT**：本阶段实际增加了什么行为验证能力？
2. **HOW**：怎样用时域扰动验证 M1 的局部稳定性预测？
3. **RESULT**：10 个候选中哪些支持映射，哪些暴露异常？
4. **ACCURACY**：M1/M2 BW、UGF、局部 PM 的误差多大？
5. **RELIABILITY**：测量在哪些参数范围和测试条件下可信？
6. **ALLOCATION VALUE**：哪些证据可以帮助 Agent 更可靠地寻找可行 BlockSpec？
7. **NEXT**：是否建议建立 M2-Fast、多保真映射，或继续研究现有 M1 的适用域？

特别说明：

本阶段不要求严格证明任意周期时变 CPPLL 的 PM，也不要求完成全域稳定性证明。

允许得出：

“当前局部 PM/UGF 映射在部分参数域内具有工程预测价值，但尚不构成完整周期系统稳定性认证。”

这属于有效的科研结论。

完成后停止，不自行开展 Stage 4.3、不训练新的黑盒预测器、不修改 Agent 策略，不自行修改正式 SystemSpec 或 Block Space。
