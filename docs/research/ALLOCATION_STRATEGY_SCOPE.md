# 分配策略研究基线与后续任务

2026-11-10 用户授权的研究重心：固定现有可测、可分配的规格，集中研究Agent首次分配及验证反馈的价值。本文是研究方案，不把待实现接口写成已实现能力。阶段决策见D022；原始章程不改。

## 固定研究对象

固定Integer-N CPPLL拓扑、10 MHz参考、N=8、80 MHz输出、原Block Space及六自由变量Icp/Rz/C1/C2/f0/Kvco。每个Policy必须提交完整17输入的JointBlockSpec，固定项也要明确。沿用原M1、原理想M2及协议1.1；不为策略胜负调整模型、源谱或测量门限。

| 量 | 当前证据来源 | 在核心策略研究中的角色 |
|---|---|---|
| BW_Hz | M1快速预测；M2独立频响及数值包络 | 以M2可靠判决作研究硬约束；预测误差可作反馈 |
| PM_deg | M1连续时间名义预测 | 名义硬约束；明确不是M2周期PM认证 |
| Vctrl_required_V | M1静态调谐/域检查 | 必须在原有效域内部；不能靠其他指标抵偿 |
| lock_time_s | 固定初态、160µs窗口及步长对照 | 既有40µs条件约束和可选捕获裕量目标 |
| 输出频率 | 固定N·fref和静态调谐；M2有限窗口诊断 | 保持输入一致，不研究尚未支持的微Hz认证 |
| Jitter/非理想/恢复 | Stage6C固定Profile和独立统计协议 | 可选固定环境或后续稳健性复验；不作为Agent核心实验的前置依赖 |
| 周期PM、全局稳定、功耗、RUR | 未认证/未支持 | 不纳入本轮策略得分，不将UNKNOWN改成PASS |

研究联合可行是混合来源的条件结论，使用`RESEARCH_JOINT_FEASIBLE`；原完整SystemSpec仍可为UNKNOWN。对同一冻结研究问题，任何受支持硬约束FAIL或证据不足UNKNOWN都阻止研究可行。

## 可直接复用的基线

唯一正式入口仍是`python -m pll_allocation pipeline`。

- 默认模式保留解析/敏感度SLSQP/随机/名义/真实LLM工具辅助首发及原确定性修复，默认M2=1、repair=0。
- 多指标模式沿用Stage6B A/B/C：A解析，B原敏感度/SLSQP，C增加确定性反馈搜索。历史A/B/C定义与历史结果不修改。
- `configs/stage6b/B1.json`、`B2.json`是原冻结研究问题的逐字节发布副本；不改门限。B1为BW150–300kHz、名义PM≥50°、条件捕获≤40µs；B2为BW290–300kHz、名义PM≥70°、同一捕获条件。
- Stage5/S0–S4和Stage6A/B已公开结果只用作开发/回归资料，不能事后标为未见过的holdout。

## 下一步实现顺序

1. 在现有Runner内扩展可替换Policy，使多指标模式也能独立消费真实LLM完整候选。保持旧默认与A/B/C路径不变，不增加第二个正式pipeline。
2. 实现真正的LLM反馈修复：将可靠测量、逐约束裕量、预测误差、数值不确定度、候选历史和剩余预算交给Policy；Policy记录调整理由并提交完整新候选，由原Runner重新检查及完整TB。
3. 先做一次真实服务首发及可靠FAIL后的真实修复验收，再冻结正式多场景/多次调用研究。网络失败、无效JSON、超域、预算耗尽均保留成本，不偷偷切换为确定性候选。
4. 以等预算实验检验策略价值，再考虑是否扩大场景数；不继续以完善M1/M2或SystemSpec作为研究推进条件。

当前正式真实LLM仅支持工具辅助首次候选；`REAL_LLM_REPAIR_NOT_IMPLEMENTED`仍是实际边界。多指标模式当前只接A/B/C，尚没有真实LLM Policy接入验收。以上两项是后续Agent工作，不是本次源码归并的隐含成果。

## 如何判断反馈是否有价值

建议将新的策略研究记为独立版本`agent_allocation_v1`，不重命名历史A/B/C。先比较解析、SLSQP、确定性反馈、真实LLM首发与真实LLM反馈。随后对相同首次候选做无反馈、标量违例、结构化物理反馈的配对消融。

反馈可用信息包括：可靠BW包络及距边界裕量，M1→M2偏差，条件捕获时间及收敛状态，控制轨限/调谐余量，历史调整与失败原因。不能将严格PM未知一律当成可修复数值误差，也不能在UNKNOWN证据下宣称某个方向已获得物理支持。

先报告首次研究可行率、有限预算最终可行率、修复成功率、最坏硬约束裕量，再报告测量次数与总成本。记录每次完整M2及内部native数、M1/cheap、LLM请求/失败、wall时间；独立CPU未测就明确缺失。首发与最终候选在各自TB前写盘，所有调整重新检查全部约束。

沿用既有上限可从每arm最多6候选槽、96M1、10000cheap开始；正式实验前另冻结LLM请求上限、场景、独立调用次数、反馈暴露字段与停止规则。相同初始候选的配对试验不能当作独立首发样本。缓存命中与重复确定性候选要明确计数，不能伪装成新测量或新LLM调用。

如果反馈没有提高可行率或裕量，或只节省成本，就按实际结果报告。Stage6C现有证据仅支持两个环境下条件捕获裕量改善，未证明jitter或一般可行率增益；不得拿它替代未来Agent策略实验。
